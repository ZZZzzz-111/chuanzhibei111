## 1. 项目概述

### 1.1 项目背景

宠物正在从"看家护院"转变为"家庭成员"，但宠物主人的日常照护需求仍然高度碎片化：想给宠物做一顿营养均衡的鲜食，需要查资料算配比；宠物生病了，深夜挂不上号、找不到可靠的咨询渠道；临时出差没人遛狗；猫咪走失后缺乏高效的寻回渠道；想给宠物做美容，又不清楚该选什么造型与服务。

同时，主流宠物类应用普遍存在两个问题：**功能割裂**（喂食、医疗、社区分散在不同 App 中）与**体验同质化**（信息流 + 表单的模板化界面，缺乏情感温度）。

### 1.2 项目定位

「川知贝 · 宠物星球」是一个**纯前端可运行的一站式 AI 宠物服务平台**，以一颗可以漫步的生态星球为载体，将宠物一天的完整生活轨迹组织为六个功能模块：

> 清晨遛弯（临时遛狗官）→ 上午美容（宠物美容院）→ 白天做饭（鲜食食堂）→ 午后诊所（赛博诊所）→ 黄昏社区（宠物圈）→ 夜里寻宠（寻宠雷达）

六个模块共享同一套「一天的陪伴」设计系统，由 AI（智谱 GLM-4-flash）提供 veterinary 问诊与造型顾问两大智能能力。

### 1.3 核心价值

1. **一站式**：喂养、医疗、美容、社交、寻宠在一个入口内完成；
2. **AI 原生**：两大高频场景（问诊、造型）由大模型驱动，流式交互；
3. **零后端可运行**：采用"同构模拟后端"架构，纯浏览器即可完整体验全部功能，降低评审与部署成本；
4. **隐私自觉**：遛狗轨迹与个人信息均保存在本地，服务结束 24 小时后物理删除。

### 3.2 技术选型及理由

| 技术 | 选型理由 |
|---|---|
| React 19 + TypeScript 7 | 生态成熟、类型安全；Hooks 模式适合本项目的多状态页面（匹配流程、抽屉、弹层） |
| Vite 8 | 秒级冷启动与 HMR；自定义中间件能力强（内置 GLM 代理即基于此） |
| Tailwind CSS 4 | 原子化样式与设计 Token 天然契合"设计系统"诉求；任意值语法便于页级主题色 |
| Framer Motion 14 | 声明式动画 + `reducedMotion="user"` 原生支持无障碍动效降级 |
| @dnd-kit/core | 无障碍拖拽（键盘传感器）、轻量、可定制碰撞检测 |
| 智谱 GLM-4-flash | 见 4.1 |
| Cloudflare Workers | 免费额度充足、边缘部署低延迟、原生支持 Secret 与流式响应透传 |

### 3.3 同构模拟后端 API 层

本项目无真实后端，但为避免"演示完即废弃"的代码，我们将数据层抽象为**与 HTTP 接口同构的函数签名**，以 `localStorage` 充当服务端存储：

```ts
// services/walkApi.ts（节选）
export function createSession(input: CreateSessionInput): OperationResult & { session: WalkSession | null }
export function validateContact(value: string): string | null   // null = 通过
export function getLatestTrackView(now?: number): TrackView      // 含隐私过滤
```

三个约定贯穿全部模拟后端：

1. **验证函数返回 `string | null`**：`null` 表示通过，字符串为面向用户的错误文案，UI 层据此渲染 `role="alert"` 逐字段提示；
2. **持久化键名带模块前缀**（`cb_walk_*` / `cb_shop_*` / `cb_groom_*`），并做结构归一化，旧数据缺字段不崩溃；
3. **敏感数据有生命周期**：遛狗轨迹仅在服务进行中及结束后 24 小时内可查，过期物理删除，仅保留不含轨迹与联系方式的墓碑记录用于友好提示。

未来接入真实后端时，仅需将函数体替换为 `fetch` 调用，页面层零改动。

## 4. AI 技术方案

### 4.1 模型选型理由

| 候选 | 结论 |
|---|---|
| **GLM-4-flash（选用）** | 中文语料质量高，贴合中文宠物语境；flash 档位延迟低、免费额度充足，适合流式对话场景；官方原生 SSE 支持 |
| GPT 系列闭源接口 | 需国际支付与网络环境，演示与评审成本高 |
| 本地小模型 | 团队无 GPU 资源，推理质量与延迟不达标 |

选择**流式（SSE）**而非一次性返回：问诊与造型建议的文本量在数百字级别，流式渲染让首字在 1~2 秒内出现，感知等待时间大幅缩短。

### 4.2 集成方式

**双模式客户端**（`src/lib/glm.ts`）是本项目 AI 集成的核心设计：

```
              ┌──────────── 本地开发 ────────────┐
 前端 fetch ──▶ /api/glm/chat/completions        │ 前端携带 Key
              │ Vite glm-proxy 中间件转发          │（Key 在 .env，不入库）
              └──────────────┬───────────────────┘
                             ▼
              ┌──────────── 生产环境 ────────────┐
 前端 fetch ──▶ Cloudflare Worker czb-glm-proxy  │ 前端不携带 Key
              │ 来源白名单 + CORS + Secret 托管     │（Key 在 Worker Secret）
              └──────────────┬───────────────────┘
                             ▼
                open.bigmodel.cn（GLM-4-flash）
```

- **密钥零暴露**：生产模式由 Worker 从 Secret 注入 `Authorization`，前端 bundle 中不存在任何密钥，满足"敏感信息不得出现在公开仓库"的要求；
- **来源白名单**：Worker 仅放行 GitHub Pages 域名与本地开发地址，防止接口被第三方盗用；
- **流式透传**：Worker 将上游 SSE 字节流原样回传，前端逐字渲染。

### 4.3 提示词工程与结构化解析

两个场景各自拥有独立的 System Prompt，并在其中**预埋结构化输出标记**，使自由文本可以被程序解析并联动界面：

| 场景 | System Prompt 要点 | 结构化标记 | 解析函数 |
|---|---|---|---|
| 赛博诊所 | 兽医角色 + 输出诊断/病因/方案/护理 + 指定末尾输出药品行格式 | `【推荐药品】` + `药名｜适用｜用法｜注意` | `parseMedicines()` |
| 宠物美容院 | 美容师角色 + 造型/服务建议 + 指定输出标记 | `【推荐造型】` + `【推荐服务】` | `parseAiAdvice()` |

解析函数采用**宽容匹配**策略（允许 markdown 加粗残留、全角分隔符、缺失标头等模型抖动），解析结果驱动 UI 联动：诊所将药品渲染为"处方笺药签"，美容院提供"一键应用推荐"按钮直接勾选对应服务与造型——**让 AI 的输出成为可操作的界面状态，而不只是文字**。

### 4.4 优化策略

1. **假启动（Fake Start）**：请求发出 1.2 秒内若无首帧，保持"思考动画"而非黑屏，消除弱网下的感知空白；
2. **流式渲染**：逐字追加 + 闪烁光标，配合自动滚动到底部；
3. **请求生命周期管理**：`AbortController` 在页面卸载/重复提问时取消在途请求，防止状态错乱；
4. **优雅降级**：未配置 Key 时展示明确的引导文案而非报错；Worker 密钥缺失时返回 500 并被前端转为友好提示；
5. **无障碍**：思考与回答区域使用 `role="status"` / `aria-live`，屏幕阅读器可感知流式进度。

## 5. 核心功能实现

### 5.1 星球首页：精灵漫步与昼夜系统

- **逐帧精灵动画**：人物/小狗为横向雪碧图，通过 `background-position` 离散关键帧（`steps(1, end)`）仅取侧面行走帧，避免"正-侧-背"闪烁；每帧以 `clip-path` 裁掉相邻帧渗透的半截肢体；
- **球面漫步**：角色角度使用 `MotionValue` 驱动，`useTransform` 派生坐标——绕圆周平移但身体始终竖直，杜绝"倒走"；牵引绳为二次贝塞尔曲线（手 → 项圈，控制点下垂），随角度实时重绘；
- **昼夜系统**：天空、星球体积光均为"双图层透明度交叉淡入"实现（渐变色不可 transition，故用两个图层切换不透明度），配合满月、流星、轨道公转微光，全站尊重 `reducedMotion`。

### 5.2 临时遛狗官：匹配、轨迹与隐私

- **匹配**：宠物状态（精力旺盛/社恐）参与评分排序，匹配度实时联动进度条动画；
- **轨迹**：模拟遛狗官端每 2 秒上报一个定位点（41 点完整路线 ≈ 2km），实时地图以"已走实线 / 待走虚线"双轨呈现，支持回放与逐点时间戳气泡；
- **隐私窗口**：`canViewTrack()` 依据服务状态与 24 小时窗口判定；`pruneExpiredSessions()` 到期物理删除轨迹并生成墓碑记录，测试覆盖"过期即不可见"。

### 5.3 鲜食食堂：拖拽配餐与商店

- 12 种食材携带真实营养字段（蛋白质/钙/磷/热量），钙磷比落在 40%~70% 健康区间之外时给出针对性建议；
- 修复了 dnd-kit 的两个深层问题：① `useDroppable` 必须在 `DndContext` 子组件中调用（注册才能进入 Provider 的 store）；② 配合 `DragOverlay` 必须使用 `pointerWithin` 碰撞检测（默认 `rectIntersection` 以原始元素矩形判定，跨栏拖放永远失败）；
- 粮食商店购物车为三步抽屉（列表/结算表单/成功态），表单验证复用统一范式。

### 5.4 赛博诊所：AI 问诊与处方笺

问诊流 `idle → thinking → streaming → done/error` 五态管理；AI 回答中的药品清单被解析为"处方笺"结构化卡片，诊断完成时盖下红色"AI 生成 · 仅供参考"印章——**将免责声明转化为有形的视觉仪式**。

### 5.5 寻宠雷达

自定义关键词与预设标签统一参与匹配（含去重、长度校验、回退展示），雷达扫描使用 conic-gradient 扇形 + 扩散波纹，线索点支持气泡详情。

### 5.6 宠物圈

CSS multi-column 瀑布流（2/3/4 列响应式），封面高度轮换制造错落；点赞、收藏、详情弹层全部本地闭环。

### 5.7 宠物美容院：AI 顾问与变身镜

体型计价系数（×1 ~ ×1.6）反映真实美容院定价逻辑；预约提交后"变身镜"以四阶段动画（毛糙 → 泡沫浴 → 吹干 → 蝴蝶结完成）呈现服务过程，阶段字幕经 `aria-live` 播报。

## 7. 创新点说明

### 7.1 技术创新点

1. **同构模拟后端 API 层**：以 localStorage 充当服务端存储、函数签名与 HTTP 同构的"可替换数据层"，让纯前端项目具备后端工程的验证、持久化与生命周期管理能力，未来可无缝迁移真实后端；
2. **双模式 AI 客户端**：同一份业务代码在开发环境走 Vite 中间件代理、生产环境走 Cloudflare Worker，密钥在生产链路中由 Worker Secret 托管，前端 bundle 零密钥，兼顾 CORS、安全与成本；
3. **dnd-kit 深层问题修复**：定位并修复了 `useDroppable` 必须处于 `DndContext` 子组件的作用域问题，以及 `DragOverlay` 场景下必须使用 `pointerWithin` 碰撞检测的问题（默认 `rectIntersection` 在跨栏拖放中永远失败）；
4. **雪碧图逐帧动画的工程化**：正面/背面/侧面混合帧的筛选、逐帧 `clip-path` 防渗透、`prefers-reduced-motion` 降级，让像素精灵图在 React 中稳定运行；
5. **双层渐变交叉淡入的昼夜系统**：以"双图层不透明度切换"绕开 CSS 渐变不可过渡的限制，实现天空、星球体积光的无缝昼夜过渡；
6. **SVG 路径动画的组合应用**：牵引绳贝塞尔曲线实时重绘、`animateMotion` 沿路径小跑、`offset-path`/`animateMotion` 与 `prefers-reduced-motion` 的协同降级。

### 7.2 应用创新点

1. **「一天的陪伴」叙事化设计系统**：六个功能模块映射一天的六个时段，以统一的设计 Token 与"每页一个记忆点"（牵引绳、处方印章、变身镜、雷达扫光……）形成完整的情感化产品叙事；
2. **有形的隐私设计**：遛狗轨迹的 24 小时保留窗口、到期物理删除与墓碑提示，将隐私合规从"条款"变为用户可感知的产品行为；
3. **AI 输出的界面化**：AI 回答不止于文字——药品解析为处方笺、造型建议一键应用为界面状态，形成"对话 → 结构化 → 可操作"的闭环；
4. **免责声明的仪式化**：诊所"红印章"将 AI 免责声明做成盖章动作，兼顾合规提示与产品记忆点；
5. **零注册即用**：任意昵称 + 手机号即可体验全部功能，降低评审与演示门槛。

## 8. 总结与展望

### 8.1 总结

项目在纯前端条件下完整实现了六大模块的产品闭环与两条 AI 智能链路，建立了可复用的同构数据层、双模式 AI 客户端与叙事化设计系统；27 项集成测试与全量类型检查保障了工程质量。团队在开发中沉淀的关键经验包括：第三方库的作用域与碰撞检测陷阱、密钥托管的正确姿势、以及"动画服务叙事而非炫技"的设计纪律。

3. **地图能力**：寻宠雷达与遛狗轨迹接入真实地图服务与 LBS；
4. **多端**：以 Capacitor/Taro 输出移动端 App 与小程序；
5. **国际化**：多语言与多地区宠物医疗资源适配。
